エージェンシーのAIツール：MCPでツール乱立から抜け出す方法

AIのサブスクリプションが10本あるのに、何もつながっていない。ツールが多いエージェンシーほど成果が上がらないことが多いのはなぜか、そしてModel Context Protocolがチームの普段の作業場所にデータを届ける仕組みを解説します。

この記事が答える問い

「自社のエージェンシーはどのAIツールを使うべきか。ツールの混乱に陥らずに統合するには、どうすればよいか」

結論ツールからではなく、最も時間を食っているワークフローから始めましょう。Claudeのような AIアシスタントを中心となるワークスペースに据え、Model Context Protocol（MCP）などのオープンなインターフェースでデータを接続します。業務ごとに新しいダッシュボードを増やす必要はありません。重要なのは、統合、トレーサビリティ（追跡可能性）、そして明確な承認ルールです。

この記事のポイント

  • AIツールを増やしても成果は増えません。統合がなければ、データのサイロ化、作業の重複、特定の個人に依存したナレッジが生まれます。
  • Model Context Protocol（MCP）は、AIアシスタントがデータソースやツールに直接アクセスできるようにするオープン標準です。新たなダッシュボードは必要ありません。
  • 大手エージェンシーグループは、ガバナンスと人による説明責任を前面に出してAIエージェントを売り込んでいます。独立系エージェンシーも、同じくらい明確に統制の仕組みを示すべきです。
  • 正しい順序は、ワークフロー、データソース、インターフェース、ルール。ツールを選ぶのはその後です。

エージェンシーにはどんなAIツールが必要でしょうか。多くの人が思うより少なく、ただし、より緊密につながっていることが条件です。ボトルネックは、足りないツールではなく、足りない統合であることがほとんどです。データは五つのシステムに散らばり、チームごとにお気に入りのチャットボットがあり、最後には誰かがスクリーンショットをスライドに貼り付けています。

一方、大手エージェンシーグループは、種類の多さよりもつながりに賭けています。Digidayによると、Dentsuのメディアエージェンシー、Caratは、NBCUniversal、FreeWheel、AI企業のNewtonと共同で、アップフロント（米国のテレビ広告の事前商談）におけるプランニング、バイイング、最適化のためのエージェントを開発しています。Tinuitiは、計測ソリューション「Bliss Point」向けのMCPサーバーを公開し、計測レイヤーをAIエージェントに開放するとともに、オーディエンス、クリエイティブ、メディア、計測のデータを一か所に集約しました。そしてWPP Mediaは、「エージェント型メディアバイイングでは、ガバナンスと人による説明責任が中核を成す」と強調しています。

AIツールが増えるほど、成果が下がることが多いのはなぜ？

新しいツールを入れるたびに、新しい孤島が生まれるからです。ソーシャルリスニングツールは会話を知っていても、メディアデータを知りません。チャットボットは見事な文章を書きますが、クライアントのことは何も知りません。レポーティングツールには数字があっても、文脈がありません。これらをつなぐのは人間で、その手段はコピー＆ペーストです。

そこに隠れたコストが加わります。重複するライセンス。ダッシュボードごとのオンボーディング。シャドーAI、つまり誰の承認もないまま、クライアントデータが通り抜けていく個人アカウント。そして、どのツールでどのプロンプトが効くかを知る一人に依存したナレッジ。

クライアントがデータ保護とデータ主権を厳しく見ているドイツのエージェンシーにとって、この乱立は非効率なだけではありません。次のピッチのアンケートで露呈するリスクです。

全体がツールの総和以上になる理由

システム理論には、シンプルな説明があります。システムは部分の総和以上のものです。性能は、部分同士の関係から生まれるからです。共通の楽譜を持たない名ソリストたちのオーケストラは、交響曲ではなくチューニングの音に聞こえます。

エージェンシーのテックスタックに当てはめると、個々のAIツールの質は、全体の性能についてほとんど何も語りません。大切なのは、データ、ツール、人が互いに対話できているかどうかです。ツールだけでは傑作は作れません。ハーモニーは、ツールが息を合わせてこそ生まれます。

だから問題は、多くの場合テクノロジーではなくアーキテクチャにあります。楽器は買ったのに、楽譜を忘れているのです。

MCPとは何か。エージェンシーにとってなぜ重要なのか？

MCPはModel Context Protocolの略です。ClaudeのようなAIアシスタントが外部のデータソースやツールにアクセスできるようにするオープン標準です。万能のコンセントのようなものだと考えてください。データソースごとに個別の連携やダッシュボードを作る代わりに、アシスタントが一つのインターフェースを通じてすべてと対話します。

エージェンシーにとって、これは前提を変えます。これまでの統合とは、データをエクスポートしてツールに読み込み、結果をまたコピーして取り出すことでした。MCPならデータはその場所にとどまり、チームは普段の作業場所で質問を投げかけます。「競合は10月初めから、どんなメッセージを打ち出しているか」は、インサイトチームへのチケットではなく、チャットでの質問になります。

Defy MCPの仕組みはまさにこれです。チームはClaudeの中で競合、オーディエンス、会話のデータに直接問い合わせます。同僚に聞くような感覚で、新しいダッシュボードを覚える必要はありません。Tinuitiが計測データを同じ方法でAIエージェントに開放していることは、今後の方向性を示しています。データはもうダッシュボードに閉じ込めておくものではなく、問い合わせられるものになるのです。

AIツールを6ステップで統合するには？

  1. 棚卸しをする。誰が、どのAIツールを、何のために、どのデータで使っているか。個人アカウントについても、はっきり尋ねましょう。責めない姿勢で聞かなければ、正直な答えは返ってきません。
  2. 時間を食う業務を三つ選ぶ。典型的な候補は、競合監査、月次レポート、ピッチのリサーチです。現在どれくらい時間がかかっているかを記録します。
  3. インターフェースを一つに絞る。チームがAIを使って作業する場所を決めます。インターフェースを増やすなら、それ相応の理由が必要です。
  4. データはコピーせず、つなぐ。MCPなどのインターフェースで直接問い合わせられるデータソースを確認します。エクスポートでしか使えないものは、後回しのリストに入れます。
  5. 導入前にルールを決める。クライアントに出す前に人がチェックするアウトプットは何か、誰が支出を承認するか、どのクライアントデータをどのシステムに入れてよいかを決めます。その場には、データ保護責任者も加えましょう。
  6. 試行し、測定し、整理する。1社のクライアントで6週間テストし、ステップ2で記録した時間と比較して、なくても誰も困らないツールは解約します。

独立系エージェンシーは、ホールディングカンパニーから何を学べるか？

Digidayの報道で目を引くのは、技術そのものよりもトーンです。エージェンシーグループは、統制を軸にエージェントを売り込んでいます。Digidayによると、WPP Mediaは、財務やアクティベーションに関する判断について、明確な統制、承認のしきい値、責任を負う人による監督を求めています。Dentsuでは、あらゆることに今も人による監督が必要だという方針です。

独立系にとって、これは一つの教訓です。クライアントがためらう理由は、技術そのものよりも、コントロールを失うことへの不安にあります。誰がどのアウトプットをチェックするのか、主張の根拠はどこにあるのか、データはどこにあるのかを説明できれば、規模を問わず信頼を得られます。

違いは、ホールディングカンパニーが潤沢な開発予算でスタックを構築するのに対し、独立系エージェンシーはより賢く組み合わせる必要があることです。データ、問い合わせ、自動化をまとめるDefyプラットフォームのようなプラットフォームは、社内にデータサイエンスチームがなくても同等のレベルに近づくための一つの方法です。

あらゆるAIベンダーに何を尋ねるべきか？

  • データはMCPなどのオープンなインターフェースで問い合わせられますか。それとも、自社のダッシュボードの中だけですか。
  • システムが示すあらゆる主張を、情報源までたどれますか。
  • データはどこに保存され、誰がアクセスでき、私たちのプロンプトはどう扱われますか。
  • そのツールは実際にどのワークフローを置き換え、その結果、どの既存ツールを解約できますか。

最後の質問に答えが返ってこないなら、買っているのはツールではありません。楽譜のない楽器が、また一つ増えるだけです。

よくある質問

Model Context Protocol（MCP）とは、どのようなものですか？

MCPは、ClaudeのようなAIアシスタントが外部のデータソースやツールにアクセスできるようにするオープン標準です。データをエクスポートしてチャット画面に貼り付ける代わりに、アシスタントがデータソースに直接問い合わせます。エージェンシーにとっては、ダッシュボードが減り、コピー＆ペーストが減り、最新のデータに基づく回答が得られるということです。

エージェンシーにはAIツールがいくつ必要ですか？

決まった数はありませんが、目安はあります。できるだけ少なく、必要なだけ深く統合すること。中心となるワークスペースが一つ、競合・オーディエンス・パフォーマンスのデータソースの接続、そして定型的なデリバリー業務の自動化があれば、多くのニーズをカバーできます。新しいツールを加えるなら、機能が増えるだけでなく、ワークフローが測定可能な形で改善されることが条件です。

エージェンシーでシャドーAIを防ぐには？

禁止するだけではほとんど効果がありません。公式のツールで足りなければ、人は個人用のツールに移ってしまうからです。それよりも、本当に役立つ承認済みのインターフェースを用意し、クライアントデータの扱いについて明確なルールを定め、どのツールが使われているかを定期的に確認することです。良いツールを提供すれば、抜け道は不要になります。

AIエージェントはメディアプランナーやストラテジストに取って代わるのでしょうか？

現時点の根拠からは、そうは言えません。Digidayによると、プランニングやバイイング向けのエージェントを開発している大手エージェンシーグループでさえ、人による監督と承認のしきい値を重視しています。エージェントが担うのはレポーティングやモニタリングといった反復的なタスクで、判断、優先順位付け、クライアントへの説明責任はチームに残ります。
